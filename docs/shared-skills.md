# 共享技能

## 安装与所有权

Ua 的 19 个工具配置均设有技能部署目标。通过对应卡片安装时，134 个技能连同随附脚本和参考资料
会部署到该配置解析后的技能库根目录，并在库根目录生成 `INDEX.md`。配置变量及目标路径见
[环境变量与路径](env-vars.md)；Doubao 的目标仍取决于该文档所述环境变量是否可解析。

Visual Studio Code 使用当前用户的 `~/.agents/skills` 作为共享库。Copilot 指令仍写入原来的独立位置；
`VSCODE_COPILOT_HOME` 只影响指令，不改变共享技能库。

共享目录只有 Visual Studio Code 卡片一个管理者。其他卡片使用各自独立的技能目录，
不会将同一共享文件登记为多个安装所有者。安装前备份同名原文件；检测到已管理文件被编辑时
停止并回滚，不覆盖修改。卸载会恢复原文件或移除生成文件，因此依赖共享库的其他客户端也会失去这些生成技能。

2.2.4 为 Devin Desktop/Windsurf、Gemini CLI、Qwen Code、Trae、CodeBuddy、Cline 和 Copilot CLI
补充了技能部署目录，其他配置的根目录保持原样。生成索引和提示词更新沿用用户修改保护、备份与事务回滚；
已有指令文件的 UTF-8 BOM 保持不变。

生成任意技能库的 `INDEX.md` 时，Ua 先在内存中规范化读取的内容，再解析索引元数据。catalog `name` 使用
实际技能目录名（canonical directory key），`description` 是规范化后的摘要，最多 1024 个字符。
每个条目另记录实际 `SKILL.md` 文档的绝对路径；这些 catalog 字段不是原始 Front Matter 的完整副本。
共享库原有的部署时名称与描述规范化行为保持不变。非共享库中的已部署 `SKILL.md` 保持原文，其中声明的
`name` 可以与 catalog 目录键不同；这种差异不改变索引键或按目录读取正文的规则。

## 原生发现

支持 `~/.agents/skills` 的本地客户端可以直接发现共享库。Visual Studio Code 重载窗口后新建会话，
运行 `Chat: Open Customizations`，检查 Skills 中的来源路径。可以输入 `/技能目录名` 手动调用，
也可让代理按任务与描述选择技能。不同版本或插件的命令和支持目录可能不同。

安装目录不等于每次对话都加载全部正文。客户端通常先读取名称和描述，再按需读取
`SKILL.md` 及其引用的配套文件。界面显示的是本地部署数，不代表某次模型调用已使用该技能。

## 提示词中的发现入口

每份安装后写出的提示词副本都包含 `# Ua Skill Discovery` 发现块，以紧凑 JSON 字段 `root`、`index`、
`count` 指示该配置的技能库根目录、索引路径和技能数量。发现块只添加到部署副本，不改写原始提示词资源文件。

只有全部受长度上限约束的实际渲染目标都能容纳完整清单时，才在提示词中内联全部 134 个精确技能目录名。
任一目标容纳不下时，省略可选的内联名称清单，仍保留紧凑 JSON 和发现规则。全部 134 个实际技能目录名、
规范化摘要和实际文档绝对路径始终保存在对应技能库的 `INDEX.md` 中；这不是原始 Front Matter 的
完整元数据转储。技能正文和配套文件仍按需读取，不会全部写入提示词。

发现规则按当前会话具备的能力使用以下入口：

1. 优先使用客户端已经提供的原生技能名称和描述，选择与任务匹配的技能。
2. 需要补充发现且具备文件读取能力时，读取发现块中 `index` 指向的本地 `INDEX.md`，再读取匹配目录下的
   `SKILL.md` 及所需配套文件。
3. 本地读取入口不可用时，如会话已配置并启用相应 MCP 工具，调用 `list_skills` 发现技能、`read_skill`
   读取正文，并用 `read_asset` 按需读取配套文本文件；遵循工具返回的分页字段继续读取。

发现块不会自动赋予文件访问能力或启用 MCP，也不保证模型一定选择或执行某个技能。普通聊天窗口及远程环境
仍需具备相应工具能力、可访问路径和配置，详见下文“模型与运行环境”。

## MCP 客户端

发布包包含独立的 `ua-skills-mcp.exe`（Windows）或 `ua-skills-mcp`（macOS/Linux），
只依赖包内 Qt 运行库，不需要 Node 或 Python。

在 Visual Studio Code 卡片弹窗的 MCP 下拉框选择客户端格式，点击复制图标，并合并到客户端现有配置：

- `MCP: Visual Studio Code`：使用 `servers` 根节点，合并到用户级 MCP 配置或项目 `.vscode/mcp.json`。
- `MCP: 通用`：使用 `mcpServers` 根节点，适用于采用该约定的插件；以插件实际配置格式为准。
- `MCP: Codex`：复制 `[mcp_servers.ua-skills]` TOML 节，合并到 Codex 的配置。

不要用片段覆盖整个已有配置。复制结果包含当前发布包中服务程序的绝对路径以及共享目录的绝对路径。
移动发布包后需要重新复制配置；更新包保留同一安装位置时路径无需更改。
Windows 更新前请停止客户端中的该 MCP 服务；检测到服务文件被占用时，Ua 会保留主窗口并提示重试。

启动服务并在客户端确认工具可用：

1. 调用 `list_skills`，查看技能名称、描述和资源列表。
2. 调用 `read_skill`，指定返回的技能名称，读取完整指令。
3. 使用 `read_asset` 读取该技能下的 UTF-8 文本参考资料或脚本；遵循返回结构中的分页字段继续读取。

`list_skills` 的 `offset` 和 `limit` 按技能条目计数；`read_skill`、`read_asset` 按 Unicode
码点计数。返回的 `nextOffset` 为下一页起点，`null` 表示结束。二进制资源仍随原生技能包部署，
MCP 文本读取接口会拒绝二进制内容。

服务仅通过标准输入输出提供 JSON-RPC MCP 协议，不监听网络端口，不执行脚本，
也不提供任意目录读取或写入工具。它只读取指定技能库中的有效技能及配套文件。

## 模型与运行环境

技能由代理或插件加载，不由模型名称决定。同一个支持工具调用的客户端切换本地、GitHub Copilot
或其他云端模型时，可保留同一技能目录/MCP 配置。具体是否选择、读取和执行技能仍由客户端能力、
模型工具调用及会话设置决定；普通聊天窗口不会仅因目录存在而获得文件访问能力。

WSL、SSH、容器及其他远程会话有自己的文件系统和执行环境。应在该环境部署共享库与相应平台的服务程序，
而不是把 Windows 可执行文件路径直接填入远程 Linux 配置。

## 完整性与修复

- **缺附件**：技能正文引用的本地脚本或参考资料未包含在 Ua 资源包中。重复安装同一个缺件版本不会补齐文件；应先更新到包含这些附件的修复版。
- **需修复**：本机已登记的技能缺少文件、安装清单仍是旧版本，或目录被链接重定向。通过对应工具卡片重新安装，可补齐文件并更新安装清单；不要直接删除整个客户端配置目录。
- **工具数量**：表示在多少个工具目录中发现技能或安装记录，不代表某次会话已经调用技能，也不替代完整性检查。

2.2.4 补齐了遗漏的随附文件，并为全部工具配置增加技能库索引和提示词发现入口。更新 Ua 后，请在需要使用的
工具卡片重新执行一次安装，以部署技能、索引和发现块，然后重载客户端或新建会话。
仅更新 Ua 可执行程序，不会擅自改写各客户端已安装的技能或提示词。
检测到用户修改时，重新安装仍会停止并保留现状；先备份并合并自己的修改，再按提示处理冲突。

技能附带脚本只作为文件部署，不会在安装时自动执行。技能文档要求的 Python、Node、第三方工具、
目标项目源码和运行环境属于单独依赖，不因“附件完整”而自动安装或启用。
